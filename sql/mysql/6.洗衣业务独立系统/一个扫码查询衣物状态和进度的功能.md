

我们需要设计一个扫码查询衣物状态和进度的功能。用户（员工或客户）通过扫描衣物上的二维码，可以获取该衣物的当前状态和清洗进度。

步骤：

1. 生成二维码时，二维码内容是一个URL，包含衣物的唯一编码（garment_code）作为参数，指向我们后端的一个接口。

   例如：https://yourdomain.com/garment/tracking?code=garment_code

2. 当用户扫描二维码时，会访问这个URL，后端根据code参数查询该衣物的状态和流转记录。

3. 后端返回一个展示页面（如果是员工在内部系统使用，可以返回详细数据；如果是客户，可以返回一个简洁的状态页面）或者根据请求头返回JSON数据（如果是移动端APP调用）。

实现方案：

方案一：直接通过网页访问

扫描二维码 -> 打开浏览器 -> 访问后端接口 -> 后端返回HTML页面展示信息

方案二：通过APP扫码（如果你们有APP）

扫描二维码 -> APP解析出URL -> APP提取code参数 -> APP调用后端API获取数据 -> APP展示信息

这里我们假设需要同时支持网页和APP，所以后端需要支持两种返回格式（根据请求头Accept判断，或者通过URL后缀区分）。

接口设计：

1. 网页访问的接口（返回HTML）：

   GET /garment/tracking?code={garment_code}

2. 提供数据的API接口（返回JSON）：

   GET /api/garment/tracking?code={garment_code}

注意：二维码中的URL应该是网页访问的接口，这样即使没有APP，用手机浏览器也能查看。

具体实现：

首先，我们需要一个根据衣物编码查询衣物状态和流转记录的服务。

步骤：

1. 根据garment_code查询衣物基本信息（当前状态、所属订单明细等）
2. 根据garment_code查询衣物流转记录（按时间倒序）
3. 根据请求类型返回不同格式的数据
