步骤：

1. 生成二维码时，二维码内容是一个URL，包含衣物的唯一编码（garment_code）作为参数，指向我们后端的一个接口。

   例如：https://yourdomain.com/garment/tracking?code=garment_code

2. 当用户扫描二维码时，会访问这个URL，后端根据code参数查询该衣物的状态和流转记录。

3. 后端返回一个展示页面（如果是员工在内部系统使用，可以返回详细数据；如果是客户，可以返回一个简洁的状态页面）或者根据请求头返回JSON数据（如果是移动端APP调用）。

实现方案：

方案一：直接通过网页访问

扫描二维码 -> 打开浏览器 -> 访问后端接口 -> 后端返回HTML页面展示信息

方案二：通过APP扫码（如果你们有APP）

扫描二维码 -> APP解析出URL -> APP提取code参数 -> APP调用后端API获取数据 -> APP展示信息

这里我们假设需要同时支持网页和APP，所以后端需要支持两种返回格式（根据请求头Accept判断，或者通过URL后缀区分）。

接口设计：

1. 网页访问的接口（返回HTML）：

   GET /garment/tracking?code={garment_code}

2. 提供数据的API接口（返回JSON）：

   GET /api/garment/tracking?code={garment_code}

注意：二维码中的URL应该是网页访问的接口，这样即使没有APP，用手机浏览器也能查看。

ZXing-js/browser 是一个强大的 JavaScript 条码扫描库，基于 Google 的 ZXing（Zebra Crossing）库开发。它支持多种条码格式，包括 QR Code、Data Matrix、Aztec、PDF417 等。下面是如何在网页中集成 ZXing-js/browser 实现条码扫描的完整方案。







我们注意到在Safari中直接请求权限的步骤没有成功（没有打印成功日志）。这可能是由于Safari的权限请求机制不同。在Safari中，必须在用户交互（例如点击事件）中直接调用getUserMedia，否则可能会被阻止。但是，在我们的代码中，这个调用是在initScanner函数中，而initScanner函数是由父组件通过prop变化触发的，可能不是由用户交互直接触发的。

为了解决这个问题，我们需要确保在Safari中，getUserMedia的调用是由用户交互（例如点击按钮）直接触发的。我们可以调整代码结构，将Safari的权限请求提前到用户点击按钮的时刻。

然而，在我们的当前结构中，用户点击的是父组件中的按钮，然后父组件通过prop控制子组件的显示，子组件在显示时进行初始化。对于Safari，我们需要在用户点击按钮时直接请求权限，然后再显示扫描组件。

修改方案：

1. 在父组件中，当点击扫描按钮时，如果是Safari浏览器，则先请求摄像头权限。
2. 权限请求成功后再显示扫描组件。

```
ngrok http 4096
```

```
npx localtunnel --port 4096
```
